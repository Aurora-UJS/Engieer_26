# asdRoboMaster 工程机器人嵌入式软件说明文档

> **项目名称**：Engineer_26（RMtextH7）
> **目标平台**：STM32H723VGTx（Cortex-M7, 1 MB Flash, 560 KB RAM）
> **编程语言**：C11
> **构建系统**：CMake + arm-none-eabi-gcc 10.3

---

## 1. 系统架构

### 1.1 系统层级总览

本项目采用 **分层架构**，从下到上可划分为以下五个层次。各层之间通过明确定义的接口进行通信：下层为上层提供硬件抽象与基础服务，上层通过调用下层的 API 完成具体业务逻辑。这种分层设计使得硬件驱动变更不会影响业务逻辑代码，同时也便于模块级独立测试与复用。

```text
┌─────────────────────────────────────────────────────┐
│                   应用任务层 (Task)                   │
│  Chassis_Task │ Arm_Task │ Referee_Task │ IMU_Task  │
│  Watchdog_Task│ Remoter  │ Trajectory_Publisher ...  │
│                                                     │
│  ·调用 Module API 完成控制决策                        │
│  ·通过 FreeRTOS 调度并行运行                          │
│  ·任务间通过【全局变量 / osThreadFlags】交换数据       │
├──────────────────── ▲ 调用 ─────────────────────────┤
│                  功能模块层 (Module)                   │
│  Motor(DJI/DM) │ DBUS │ IMU │ PID │ 运动学解算       │
│  裁判系统协议 │ 上位机通信 │ 滤波器 │ 功率控制 │ 超级电容 │
│                                                     │
│  ·封装传感器/执行器的数据解析与控制算法                 │
│  ·向上提供 Init / Refresh / Ctrl 等函数接口           │
│  ·向下调用 BSP 的 CAN/UART 收发函数                   │
├──────────────────── ▲ 调用 ─────────────────────────┤
│               板级支持包 (BSP)                        │
│  CAN │ UART │ SPI(BMI088) │ DWT │ GPIO │ Buzzer     │
│                                                     │
│  ·二次封装 HAL 外设，屏蔽寄存器细节                    │
│  ·CAN: FreeRTOS 链表管理 + 中断回调自动分发            │
│  ·UART: DMA 收发 + Hook 回调函数机制                  │
├──────────────────── ▲ 调用 ─────────────────────────┤
│               RTOS / 中间件层                         │
│              FreeRTOS (CMSIS-RTOS v2)                │
│              CMSIS-DSP (ARM Math)                    │
│                                                     │
│  ·提供多线程调度、信号量、线程标志、内存管理            │
│  ·提供浮点 PID / 矩阵 / 三角函数等 DSP 运算           │
├──────────────────── ▲ 调用 ─────────────────────────┤
│               硬件抽象层 (HAL)                        │
│         STM32 HAL Driver (STM32CubeMX 生成)          │
│    FDCAN │ UART │ SPI │ TIM │ DMA │ CRC │ GPIO      │
│                                                     │
│  ·最底层硬件访问，由 CubeMX 自动生成                   │
│  ·提供标准化外设操作函数（Init/Start/IRQHandler等）    │
└─────────────────────────────────────────────────────┘
```

### 1.2 各层功能说明

#### 1.2.1 硬件抽象层（HAL）

由 STM32CubeMX 自动生成，位于 `Core/` 和 `Drivers/` 目录。提供对 STM32H723VGTx 芯片外设的标准化访问接口：

| 外设                     | 用途                                             |
| ------------------------ | ------------------------------------------------ |
| **FDCAN1/2/3**     | 电机通信（DJI 3508、DM 达妙电机）、外部 IMU 通信 |
| **UART5**          | DT7 遥控器（DBUS 协议）接收                      |
| **UART7**          | 自定义控制器 / 裁判系统数据接收                  |
| **USART1/2/3/10**  | 上位机通信、调试串口等                           |
| **SPI2/SPI6**      | 板载 BMI088 六轴 IMU                             |
| **TIM1/2/3/12/17** | PWM 输出（蜂鸣器）、系统时基等                   |
| **DMA**            | UART 异步收发                                    |
| **CRC**            | 裁判系统协议 CRC 校验                            |

#### 1.2.2 RTOS / 中间件层

| 中间件              | 版本/来源                        | 说明                                                                                                                                                         |
| ------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **FreeRTOS**  | Middlewares/Third_Party/FreeRTOS | 实时操作系统内核，CMSIS-RTOS v2 封装。提供多任务调度、信号量、线程标志等机制。                                                                               |
| **CMSIS-DSP** | Drivers/CMSIS/DSP                | ARM 官方 DSP 库，提供浮点数学运算（PID、矩阵运算、三角函数等），编译时定义 `ARM_MATH_CM7` 启用 Cortex-M7 优化。链接静态库 `libarm_cortexM7lfdp_math.a`。 |

#### 1.2.3 板级支持包（BSP）

位于 `source/bsp/`，对 HAL 外设进行二次封装，提供统一、简洁的驱动接口：

| BSP 模块                | 目录              | 功能                                                                          |
| ----------------------- | ----------------- | ----------------------------------------------------------------------------- |
| **CAN 通信**      | `bsp/can/`      | 封装 FDCAN 收发，基于 FreeRTOS 链表管理多 ID 消息的注册、查找与回调分发       |
| **UART 通信**     | `bsp/uart/`     | 封装 DMA 收发，提供 Hook 回调机制（`uart_rx_hook`），支持多路 UART 并行接收 |
| **BMI088 IMU**    | `bsp/BMI088/`   | 板载六轴 IMU（加速度计 + 陀螺仪）SPI 驱动                                     |
| **DWT 计时**      | `bsp/dwt/`      | 利用 Cortex-M DWT 周期计数器，提供微秒级高精度计时与延时                      |
| **Buzzer 蜂鸣器** | `bsp/buzzer/`   | PWM 驱动蜂鸣器，支持频率与占空比设置，用于报警提示                            |
| **GPIO**          | `bsp/gpio/`     | 通用 GPIO 操作封装                                                            |
| **Keyboard**      | `bsp/keyboard/` | 键盘/鼠标数据结构定义（WASD + 鼠标，位域映射）                                |

位于 `source/module/`，提供与具体硬件无关的功能抽象：

各层之间并非简单的"上层调用下层"，而是通过多种通信机制实现双向数据流动。下图展示了**层与层之间的主要通信路径及所用机制**：

#### 1.4.1 HAL → BSP：硬件中断驱动的上行数据通路

HAL 层与 BSP 层之间的通信以 **中断回调** 为核心机制，数据从硬件外设自底向上传递：

1. **CAN 接收通路**：当 FDCAN 外设 FIFO 收到新报文时，HAL 触发 `HAL_FDCAN_RxFifo0Callback()` 中断回调。BSP 层在该回调内部根据 `hfdcan` 句柄区分 CAN1/CAN2/CAN3 端口，分别调用 `fdcan1/2/3_rx_callback()`。每个回调函数通过 `fdcanx_receive()` 从硬件 FIFO 读出报文数据，然后在对应端口的 **FreeRTOS 链表**（`can1/2/3_rx_msg_list`）中按 ID 查找已注册的 `can_msg_t` 节点，将数据拷贝到该节点的 `data[]` 字段并递增 `cnt` 计数器。这一过程完全在中断上下文中完成，无需任务切换，保证了微秒级的数据更新延迟。
2. **UART 接收通路**：UART 外设通过 DMA + 空闲中断方式接收数据。当一帧数据接收完毕（空闲线检测）时，HAL 触发 `HAL_UARTEx_RxEventCallback()`。BSP 层在该回调内部根据 UART Instance 区分不同串口，更新接收计数器 `count`，并调用已注册的 **Hook 回调函数**（如 `uart5_rx_hook`）将数据上传给 Module 层。随后自动重新启动下一次 DMA 接收，实现连续无缝的数据采集。
3. **CAN 发送通路**（下行）：BSP 提供 `can_msg_send_classical()` / `can_msg_send_extended()` / `can_msg_send_fd()` 三种发送接口，内部根据 `can_msg_t.port` 字段选择对应的 FDCAN 句柄，调用 HAL 的 `HAL_FDCAN_AddMessageToTxFifoQ()` 将报文写入发送 FIFO。

#### 1.4.2 BSP → Module：注册-回调模式与轮询模式并存

Module 层与 BSP 层之间采用两种通信模式：

1. **注册-回调模式（UART）**：Module 初始化时调用 `uart_rx_init()` 注册接收缓冲区，并通过 `uart_rx_hook_reg()` 注册数据到达回调。例如 DBUS 模块在 `DBus_Init()` 中将 UART5 的接收缓冲区和长度注册到 BSP，之后每收到一帧 18 字节 DBUS 数据，BSP 中断回调会自动递增 `count` 计数器，Module 层 `DBus_Refresh()` 通过比较 `count` 与上次值来判断是否有新数据，有则调用 `get_dr16_data()` 解析。
2. **注册-轮询模式（CAN）**：Module 层的电机驱动在初始化时调用 `can_msg_add_item()` 将带有特定 ID 的 `can_msg_t` 注册到 BSP 链表。之后在任务周期中调用 `Motor_DJI_Refresh()` 或 `Motor_DM_Refresh()` 直接读取 `can_msg_t.data[]`（已由中断回调实时更新），解析出电机转速、角度、温度等字段，写入 `can_motor_t` 结构体供上层使用。发送控制指令时，Module 层填充 `can_msg_t.data[]` 后调用 `can_msg_send_classical()` 下发。

#### 1.4.3 Module → Task：函数 API 调用

Task 层通过直接调用 Module 层的函数 API 完成业务逻辑。例如：

- `Chassis_Task` 调用 `Chassis_Normal_Mode()` → 内部调用 `omni_mecanum_kinematics()` + `PID_Calc_Pos()` + `set_motor_parameter()` + `can_msg_send_classical()`，完成从运动矢量到 CAN 电机指令的整条链路。
- `jointFollowAngle` 任务调用 `Joint_Motor_Refresh()` 获取电机反馈 → 调用 `PosSpeed_CtrlMotorDM()` 下发位置-速度指令。
- `IMU_Task` 调用 `IMU_RequestData()` 发送 CAN 请求帧 → 从已注册的 `can_msg_t` 中解析欧拉角。

#### 1.4.4 Task ↔ Task：全局变量与 RTOS 同步机制

任务之间的通信主要通过以下机制：

1. **全局共享变量**（最常用）：如 `rc_info_t remoter`（遥控器数据，Remoter_Task 写，Chassis_Task / Arm_Task / Watchdog_Task 读）、`Engineer_Mode_t Engineer_Mode`（全局模式变量，Referee_Task 写，Chassis_Task / Arm_Task 读）、`IMU_data`（IMU 数据，IMU_Task 写，Rising_Upstairs_Mode 读）。由于 STM32H7 为单核处理器且所有共享变量均为简单标量或小结构体，在 2ms 周期的任务调度下不会出现一致性问题。
2. **FreeRTOS 线程标志（osThreadFlags）**：用于任务间事件通知。例如 `Trajectory_Publisher_Task` 启动后调用 `osThreadFlagsWait(TRAJ_START_FLAG, osFlagsWaitAll, osWaitForever)` 阻塞等待；当 Arm_Task 的状态机切换到轨迹模式时，通过 `osThreadFlagsSet()` 发送标志位唤醒轨迹发布任务，开始逐帧回放预定义的 656 个关节角度点（每帧间隔 30ms）。
3. **FreeRTOS 延时调度（osDelay）**：所有任务以固定周期运行（1ms / 2ms / 10ms），通过 `osDelay()` 主动让出 CPU。FreeRTOS 抢占式调度器根据任务优先级决定执行顺序，高优先级任务可打断低优先级任务。

```text
    └──────────────┘            └─────────────────────┘
           ▲
           │ IMU_data (Pitch/Yaw/Roll)
    ┌──────┴───────┐    ┌──────────────┐
    │  IMU_Task    │    │IMU_TempCtrl  │
    │ 外部DM-IMU   │    │ 板载BMI088    │
    │  (10ms)      │    │  (1ms)       │

```

从外部设备到 MCU 的通信路径，涉及以下物理总线和协议：

## 2. 运行流程

### 2.1 系统启动流程

系统上电或复位后，执行流程分为三个阶段：**硬件初始化**、**BSP 初始化** 和 **RTOS 启动**。在 RTOS 调度器启动之前，所有初始化均在单线程（裸机）环境中顺序执行，确保外设和通信总线在任务运行前已就绪。

```text
上电 / 复位
    │
    ▼
startup_stm32h723xx.s          ← 启动汇编：初始化栈指针、.bss/.data 段，跳转 main()
    │
    ▼
main()                         ← Core/Src/main.c
    ├── HAL_Init()             ← HAL 库初始化（SysTick、NVIC 分组等）
    ├── SystemClock_Config()   ← 系统时钟配置：HSE → PLL → 480MHz SYSCLK
    ├── MX_GPIO_Init()         ← GPIO 初始化
    ├── MX_DMA_Init()          ← DMA 通道初始化
    ├── MX_FDCAN1/2/3_Init()   ← FDCAN 外设初始化（3 路 CAN 总线）
    ├── MX_UART5/7_Init()      ← UART 初始化（遥控器 / 自定义控制器）
    ├── MX_USART1/2/3/10_Init()← USART 初始化（上位机通信 / 调试）
    ├── MX_SPI2/6_Init()       ← SPI 初始化（板载 BMI088）
    ├── MX_TIM1/2/3/12_Init()  ← 定时器初始化（PWM 等）
    ├── MX_CRC_Init()          ← CRC 硬件加速初始化
    ├── can_sys_init()         ← BSP CAN 系统初始化（注册消息链表、过滤器配置）
    │
    ├── osKernelInitialize()   ← FreeRTOS 内核初始化
    ├── MX_FREERTOS_Init()     ← 创建所有 RTOS 任务与信号量
    └── osKernelStart()        ← 启动调度器，控制权移交 FreeRTOS
```

**阶段说明**：

1. **硬件初始化阶段**（`HAL_Init` ~ `MX_CRC_Init`）：由 STM32CubeMX 自动生成，依次完成时钟树配置（HSE 外部晶振 → PLL 倍频至 480 MHz）、GPIO 引脚复用、DMA 通道绑定、三路 FDCAN 总线参数设置（波特率、滤波器）、UART/USART 波特率与 DMA 绑定、SPI 时钟极性配置、定时器 PWM 通道启动以及 CRC 硬件加速器使能。该阶段结束后，所有外设寄存器已正确配置，但尚未开始数据收发。
2. **BSP 初始化阶段**（`can_sys_init`）：这是从 CubeMX 自动生成代码过渡到用户自定义代码的关键步骤。`can_sys_init()` 函数初始化三个 FreeRTOS 链表（`can1/2/3_rx_msg_list`），配置 FDCAN 全局过滤器（接收 0x000~0xFFF 全部标准 ID），启动三路 FDCAN 外设并使能接收 FIFO 中断。此后，CAN 总线上的任何报文都会触发中断并被 BSP 层自动分发到已注册的节点。
3. **RTOS 启动阶段**（`osKernelInitialize` ~ `osKernelStart`）：首先初始化 FreeRTOS 内核数据结构（就绪队列、定时器链表等），然后在 `MX_FREERTOS_Init()` 中依次创建 9 个任务（见下节）。所有任务的栈空间和任务控制块（TCB）均为**静态分配**（`osThreadAttr_t` 中指定 `.stack_mem` 和 `.cb_mem`），避免了动态内存分配可能导致的碎片化风险。最后调用 `osKernelStart()` 启动调度器，此后 CPU 控制权由 FreeRTOS 接管，`main()` 函数不再返回。

### 2.2 FreeRTOS 任务创建与调度

在 `MX_FREERTOS_Init()` 中，依次创建以下线程（均为静态分配）：

```text
1. defaultTask           ← 空闲任务
2. IMU_TempCtrl          ← 板载 IMU 温控 + 姿态解算
3. Remoter_Task          ← 遥控器 DBUS 数据接收
4. jointFollowAngle      ← 机械臂关节跟随控制
5. Chassis_Task          ← 底盘 + 抬升控制
6. Referee_Task          ← 裁判系统 / 键盘处理
7. IMU_Task              ← 外部 DM-IMU 数据采集
8. Trajectory_Publisher  ← 机械臂轨迹发布
9. Watchdog_Task         ← 看门狗监控
```

所有业务任务函数在 `freertos.c` 中声明为 `__weak`，实际实现在 `source/task/` 各文件中覆盖（Override）。这种设计将 CubeMX 自动生成的框架代码与用户业务逻辑分离，确保重新生成代码时不会覆盖用户实现。

调度器启动后，各任务按照优先级进入就绪队列。由于采用 FreeRTOS 的**抢占式调度**策略，高优先级任务（Normal）可以随时打断低优先级任务（Low）。同一优先级的任务之间采用时间片轮转。所有业务任务在其主循环末尾调用 `osDelay(N)` 主动让出 CPU 并等待 N 个 tick（1 tick = 1 ms），由此形成固定周期的控制循环。

每个任务启动时通常会先执行一次 `osDelay(200)` 等待（如 `Chassis_Task`），为底层外设和传感器预留上电稳定时间，避免在电机驱动尚未就绪时发送控制指令。

### 2.3 数据流与处理过程

#### 2.3.1 遥控器数据流

DT7 遥控器通过 DBUS 协议以固定 18 字节帧格式发送通道数据。UART5 外设以 DMA + 空闲中断方式连续接收，每收到一帧完整数据后自动递增接收计数器。`Remoter_Task` 以 1ms 周期轮询，通过比较计数器变化判断有无新数据到达，有则调用 `get_dr16_data()` 进行位域拆分——将 18 字节原始数据解析为 4 个摇杆通道值（ch1~ch4，范围 ±660）、2 个拨码开关值（sw1/sw2）、鼠标三轴增量、鼠标按键状态及键盘键码。解析后的结果写入全局变量 `rc_info_t remoter`，供底盘、机械臂和看门狗等多个任务并行读取。为防止零漂，所有通道值在 ±5 以内的微小偏差被强制置零；超出 ±660 的异常数据则触发全结构体清零保护。

```text
DT7 遥控器 ──DBUS协议──► UART5 (DMA)
                              │
                              ▼
                    Remoter_Task (1ms)
                    ├── DBus_Init()       ← 注册 UART5 接收回调
                    └── DBus_Refresh()    ← 解析 18B DBUS 帧 → rc_info_t remoter
                              │
                  ┌───────────┼───────────┐
                  ▼           ▼           ▼
           Chassis_Task  Arm_Task   Watchdog_Task
           (读 remoter)  (读 sw1)   (检测超时)
```

#### 2.3.2 底盘控制数据流

底盘控制是整个系统中最核心的实时闭环链路，运行在 2ms 周期的 `Chassis_Task` 中。每个周期的处理流程为：

1. **模式判断**：`Chassis_Mode_Get()` 根据 `remoter.sw2` 确定当前模式——sw2=3 为 Normal（正常全向移动），sw2=1 为 Upstairs（上台阶联动控制），sw2=2 为 PowerOff（电机停转断电）。
2. **运动矢量计算**：在 DBUS 模式下，将摇杆 ch1/ch2/ch3 三通道分别映射为横向平移速度 x、纵向前进速度 y 和旋转角速度 ωz。在 Keyboard 模式下，WASD 四键分别映射为 ±x / ±y，鼠标 X 轴映射为 ωz（带 100 死区和限幅处理）。
3. **逆运动学解算**：`omni_mecanum_kinematics()` 根据麦克纳姆轮运动学模型，将 (x, y, ωz) 分解为 4 个车轮的目标转速。
4. **PID 闭环控制**：每个车轮独立执行 `PID_Calc_Pos()` 位置式 PID 运算，以目标转速为设定值、编码器实际转速为反馈值，输出电流控制量。输出经一阶低通滤波（LPF）平滑后，4 个电机的指令打包为 CAN 数据帧发送至 DJI 3508 电机（CAN1, ID=0x200）。
5. **抬升联动**（仅 Upstairs 模式）：在底盘控制的基础上额外启用 `Rising_Upstairs_Mode()`——将 ch2 映射为 3508 抬升电机目标速度（ch2 > 100 时强制最大速度），并利用外部 DM-IMU 的 Pitch 角反馈通过 PID 计算 DM 电机目标角度偏移量，实现车体倾斜时抬升臂的姿态自动补偿。

```text
rc_info_t remoter / keyboard_t kb_info
          │
          ▼
    Chassis_Task (2ms 周期)
    ├── Chassis_Mode_Get()       ← 根据 sw2 拨码确定模式 (Normal/Upstairs/PowerOff)
    │
    ├── [DBUS 模式]
    │   ├── Chassis_Normal_Mode()
    │   │   ├── ch1/ch2/ch3 → map() → (x, y, ωz)
    │   │   ├── omni_mecanum_kinematics() → 四轮目标转速
    │   │   ├── PID_Calc_Pos() × 4 → 电流输出
    │   │   ├── LPF 低通滤波
    │   │   └── CAN 发送 → DJI 3508 × 4 (CAN1, 0x200)
    │   │
    │   └── Chassis_Upstairs_Mode()
    │       ├── 同上（但 ch3=0 禁止 yaw 旋转）
    │       └── Rising_Upstairs_Mode()
    │           ├── ch2 → map() → 3508 抬升目标速度
    │           ├── PID_Calc_Pos() × 2 → 电流输出
    │           ├── CAN 发送 → DJI 3508 × 2 (CAN1, 0x200)
    │           ├── IMU_data.Pitch → PID → DM 目标角度偏移量
    │           └── PosSpeed_CtrlMotorDM() → DM 电机 × 2 (CAN3)
    │
    └── [Keyboard 模式]
        ├── WASD → (x, y)，mouse_x → ωz
        ├── omni_mecanum_kinematics() → 四轮目标转速
        └── 同上 PID + CAN 发送
```

#### 2.3.3 机械臂控制数据流

机械臂控制链路涉及两个协作任务：`Referee_Task` 负责数据接收与解析，`jointFollowAngle` 负责关节运动控制。

自定义控制器（物理操控手柄）的数据通过裁判系统协议封装后经 UART7 传入。`Referee_Task`（2ms 周期）调用 `CtrllerReadData()` 进行 CRC 校验和 26 字节有效载荷提取，将原始字节解析为关节控制指令并写入全局数组 `CtrllerData[26]`。同时，`Referee_KeyboardEdgeDetect()` 对键盘按键进行边沿检测——B 键切换 DBUS/Keyboard 控制逻辑，C 键切换底盘 Normal/Rising 模式。

`jointFollowAngle` 任务以 1ms 的高频率运行，确保关节跟随精度。每个周期依次完成：① `Joint_Motor_Refresh()` 刷新 6 个 DM 电机的角度/速度/扭矩反馈数据；② `Gripper_Control_Mode_Mangner()` 管理末端夹爪的开合状态机；③ `Joint_Control_Mode_Mangner()` 根据当前模式执行不同控制策略——在 Custom_Controller 模式下，将 26 字节控制器数据转换为 6 个关节的目标弧度值，经极性调整和安全限位后写入 `Target_Point[6]`；④ `Joint_Move_byPoint()` 以位置-速度（PosSpeed）模式向 6 个 DM 电机下发控制指令（CAN2/CAN3）。此外，当状态机切换到 Traj_Mode 时，通过 `osThreadFlagsSet()` 唤醒 `Trajectory_Publisher_Task`，后者以 30ms 间隔逐帧发布预定义的 656 个关节角度采样点，实现离线轨迹回放。

```text
自定义控制器 ──UART7──► 裁判系统协议解析
                              │
                              ▼
                    Referee_Task (2ms)
                    ├── CtrllerReadData()  ← 解析自定义控制器 26B 数据
                    └── Referee_KeyboardEdgeDetect() ← 键盘边沿触发
                              │
                              ▼
                   CtrllerData[26] (全局)
                              │
                              ▼
                  jointFollowAngle (1ms)
                  ├── Joint_Motor_Refresh()           ← 刷新 6 个 DM 电机反馈
                  ├── Gripper_Control_Mode_Mangner()   ← 夹爪开合状态机
                  ├── Joint_Control_Mode_Mangner()     ← 关节状态机
                  │   ├── sw1=1 → Arm_Rising_Mode     ← 预设抬升姿态
                  │   └── 默认  → Custom_Controller   ← 自定义控制器跟随
                  │       ├── Parse_ControllerData_To_CtrllerRadian()
                  │       ├── 极性调整 + 限位
                  │       └── Point_Publisher() → Target_Point[6]
                  └── Joint_Move_byPoint()            ← PosSpeed 模式下发
                      └── PosSpeed_CtrlMotorDM() × 6  ← CAN2/CAN3 发送
```

#### 2.3.4 IMU 数据流

系统同时使用两套独立的 IMU 数据源，各自服务于不同的控制需求：

**板载 BMI088**（SPI 接口）：`IMU_TempCtrlTask` 以 1ms 高频率运行，首先通过 SPI 读取 BMI088 的加速度计和陀螺仪原始数据，然后送入 Mahony 互补滤波器（初始化采样率 1000Hz）进行姿态解算，输出板载姿态角。该任务还负责 IMU 芯片的恒温控制，通过 PID 调节加热电阻的 PWM 占空比，将传感器温度稳定在设定值附近，减少温漂对陀螺仪零偏的影响。

**外部 DM-IMU**（CAN3 接口）：`IMU_Task` 以 10ms 周期运行，每个周期通过 CAN3 发送寄存器读取请求帧（`IMU_RequestData(reg=3)`），随后从已注册的 `can_msg_t` 节点中解析返回的欧拉角数据（Pitch/Yaw/Roll，单位：弧度），写入全局结构体 `IMU_data`。该数据主要服务于抬升机构的 IMU Pitch 闭环控制：`Rising_Upstairs_Mode()` 读取 `IMU_data.Pitch`，以 0° 为目标通过 PID 运算产生 DM 电机角度偏移量，补偿车体在上台阶时的俯仰变化。

```text
板载 BMI088 (SPI)                    外部 DM-IMU (CAN3)
       │                                    │
       ▼                                    ▼
IMU_TempCtrlTask (1ms)              IMU_Task (10ms)
├── BMI088_init()                   ├── IMU_RequestData(reg=3)
├── Mahony_Init(1000Hz)             ├── 解析欧拉角(pitch/yaw/roll)
└── IMUsys()                        └── IMU_data.Pitch/Yaw/Roll (rad)
    └── Mahony 互补滤波                       │
        → 板载姿态角                          ▼
                                   Rising_Upstairs_Mode()
                                   └── IMU Pitch → PID → DM 抬升角度闭环
```

#### 2.3.5 看门狗监控数据流

`Watchdog_Task` 以 1ms 周期运行，是系统安全的最后防线。其核心职责是持续监测所有关键设备的在线状态并在异常时采取保护措施：

- **DJI 3508 电机在线检测**：每 500ms 检查一次 6 个 3508 电机的 CAN 反馈计数器（`can_msg_t.cnt`）是否有变化。若某电机计数器连续 500ms 无增长，判定为离线，触发蜂鸣器报警——报警频率随离线电机数量递增，便于操作手快速判断故障范围。
- **DM 电机在线检测与错误恢复**：除在线状态监测外，还检查 DM 电机的错误码（`DM_motor_error_t`），包括过压、欠压、过流、MOS/电机过温、通信丢失和过载等故障类型。检测到在线但失能的 DM 电机时，以 200ms 周期自动发送使能指令；检测到错误码时，先清除错误再重新使能，实现故障自动恢复。
- **遥控器超时保护**：持续跟踪 `remoter` 结构体的变化。若超过 60 秒遥控器数据无任何变化（操作手可能离开或信号丢失），自动调用 `Chassis_ForcePowerOff()` 强制底盘断电，防止失控的机器人造成安全事故。

```text
Watchdog_Task (1ms 周期)
├── 3508 电机在线检测 × 6（CAN 计数器变化检测，500ms 超时）
│   └── 离线 → 蜂鸣器报警（频率随离线数量递增）
├── DM 电机在线检测 × 2 + 错误码监控
│   ├── 在线但失能 → 自动重使能（200ms 周期）
│   └── 错误码处理（过压/过流/过温 → 清错重使能）
└── 遥控器超时检测
    └── 60s 无变化 → Chassis_ForcePowerOff() 强制底盘断电
```

### 2.4 底盘模式切换状态机

底盘模式切换由两个维度共同决定：**sw2 拨码开关**（硬件层面的模式选择）和 **B/C 键**（软件层面的控制源切换）。

sw2 拨码开关直接映射为三种基本模式——PowerOff 使所有电机立即停转并输出零电流（安全停机）；Normal 允许底盘四轮全向移动同时抬升机构停转归零；Upstairs 在底盘移动的基础上联动抬升机构，启用 3508 抬升电机的速度控制和 DM 电机的 IMU Pitch 角闭环补偿。当模式从 Normal 切换到 Upstairs 或反之时，`Chassis_Task` 检测到 `last_chassis_mode` 变化并调用 `Rising_Reset_DmImuPid()` 清零 PID 积分项，消除切换冲击。

在软件层面，键盘 B 键实现 DBUS 模式与 Keyboard 模式之间的边沿触发切换。DBUS 模式下遥控器摇杆全权控制底盘和机械臂；Keyboard 模式下底盘改由 WASD + 鼠标控制，并可通过 C 键在 Normal 和 Rising 子模式之间切换。模式切换时自动保存和恢复机械臂控制模式（`Arm_Ctrl_Mode_Save/Restore`），防止切换操作污染其他子系统的状态。

### 2.5 抬升测试历程状态机（条件编译开关）

为简化上台阶动作的调试与参数标定，系统提供了一套通过条件编译宏 `CHASSIS_RISING_TEST_TRAJECTORY_ENABLE` 控制的自动化测试轨迹。当该宏设为 1 时启用，设为 0 时测试代码完全不参与编译，不占用 Flash 空间。

该状态机在操作手将 sw2 拨码切到 Upstairs 的**上升沿**时触发（仅触发一次），依次执行三个阶段：

1. **LIFTING 阶段**（持续 `LIFT_DURATION_MS` 毫秒）：底盘以 `LIFT_CHASSIS_FIXED_SPEED_RATIO` 比例的固定速度前进，抬升 3508 电机以最大速度运转（通过注入 `rc.ch2 = 660` 实现），DM 电机保持 IMU Pitch 闭环。该阶段模拟机器人前轮接触台阶并开始抬升的过程。
2. **DRIVING 阶段**（持续 `DRIVE_DURATION_MS` 毫秒）：有效底盘模式切换为 Normal，底盘以 `DRIVE_CHASSIS_FIXED_SPEED_RATIO` 比例的固定速度前进，抬升机构停转归零。该阶段模拟前轮已上台阶后继续向前推进、将后轮也推上台阶的过程。
3. **PASSTHROUGH 阶段**：底盘模式保持 Normal，操作手重新获得遥控器全权控制。若操作手在任何阶段将拨码切离 Upstairs，状态机立即回到 IDLE，所有强制注入的速度解除。

```text
拨码切到 Upstairs (上升沿触发)
          │
          ▼
  ┌───────────────┐    LIFT_DURATION_MS 到时
  │   LIFTING     │ ─────────────────────────►┌──────────────┐
  │ 底盘固定速度   │                            │   DRIVING    │
  │ 抬升3508最大   │                            │ 底盘固定速度  │
  │ DM IMU闭环    │                            │ 模式切Normal │
  └───────────────┘                            │ 抬升停转     │
                                               └──────┬───────┘
                                    DRIVE_DURATION_MS 到时│
                                                        ▼
                                               ┌──────────────┐
                                               │ PASSTHROUGH  │
                                               │ 遥控器全权    │
                                               │ 模式仍Normal  │
                                               └──────────────┘
  拨码切离 Upstairs → 任何阶段立即回到 IDLE
```

## 3. 重点功能

> **说明**：本节重点描述系统中具有自主设计特色的核心功能。每个功能从问题背景、技术方案、设计亮点三个维度展开，标注 `[待补充]` 的参数请结合实际调试数据填写。

### 3.1 麦克纳姆轮全向底盘运动控制

- **解决的问题**：工程机器人需要在比赛场地内灵活移动——前后、左右平移、原地旋转，以满足取矿、兑矿、登岛等复杂路径需求。传统差速底盘无法实现横向平移，而麦克纳姆轮底盘可以在不改变朝向的前提下向任意方向运动。
- **技术方案**：
  - 采用 4 轮全向麦克纳姆轮底盘布局，4 个 DJI 3508 减速电机分别驱动左前（ZQ）、左后（ZH）、右后（YH）、右前（YQ）车轮
  - 遥控器 3 轴输入（ch1→横移, ch2→前进, ch3→旋转）通过 `map()` 线性映射为运动矢量 `(x, y, ωz)`
  - 经 `omni_mecanum_kinematics()` 逆运动学解算，将运动矢量分解为 4 个车轮的目标转速。该函数内部实现了标准的麦克纳姆轮运动学方程，考虑了轮距和轴距参数
  - 每个电机独立执行位置式 PID 闭环（`PID_Calc_Pos()`），以目标转速为设定值、编码器反馈转速为过程变量，输出电流控制量
  - PID 输出经一阶低通滤波（LPF）平滑后打包为 CAN 帧发送（CAN1, ID=0x200，8 字节携带 4 个电机的 16 位电流值）
  - 键盘模式下支持 WASD 平移 + 鼠标 X 轴控制 yaw（含 100 死区 + 限幅），实现精确的手动微调操作
- **设计亮点**：运动学解算与 PID 控制完全封装在 Module 层，Task 层只需传入 3 个运动分量即可，便于后续扩展舵轮或其他底盘方案
- **关键参数**：`[待补充：最大速度、PID 参数 Kp/Ki/Kd、LPF 截止频率、控制周期 2ms 等]`

### 3.2 抬升机构 IMU 姿态闭环控制

- **解决的问题**：工程机器人在上台阶/上岛过程中车体会产生较大俯仰角变化，若抬升机构不做补偿，DM 电机的绝对角度会随车体倾斜而偏移，导致抬升臂不受控制。需要一种机制使抬升臂相对于水平面保持稳定。
- **技术方案**：
  - 外部 DM-IMU 模块安装在机器人底盘上，通过 CAN3 总线提供实时 Pitch 角度反馈（10ms 更新周期，单位：弧度）
  - 抬升 DM 电机采用 **位置-速度模式**（`PosSpeed_CtrlMotorDM`），可同时指定目标角度和运动速度
  - 闭环控制算法 `Rising_DmImuAngleClosedLoop()` 以 IMU Pitch 角为反馈、0°（水平）为目标，通过 PID 运算得到角度补偿量 Δθ
  - 左右两个 DM 电机对称控制——左电机目标角度为 `ZeroPoint + Δθ`，右电机为 `-(ZeroPoint + Δθ)`（符号取反），确保两侧同步补偿
  - 模式切换瞬间（Normal ↔ Upstairs）自动调用 `Rising_Reset_DmImuPid()` 清零 PID 积分项和误差累积，消除模式转换时的角度冲击
  - 3508 抬升电机的速度控制与 DM 角度闭环并行运行：ch2 摇杆映射为 3508 目标速度（ch2 > 100 时强制最大速度 `Max_Rising_Motor_Velocity`），提供抬升的线性驱动力
- **设计亮点**：将 IMU 姿态补偿与电机位置控制解耦——IMU 只负责产生角度偏移量，DM 电机的位置控制由电机内置驱动器完成，降低了控制器复杂度
- **关键参数**：`[待补充：DM 电机型号、Rising_DM_ZeroPoint 值、IMU 安装位置、PID Kp/Ki/Kd 等]`

### 3.3 六自由度机械臂关节控制

- **解决的问题**：工程机器人需要精确抓取、搬运和放置矿石资源，要求 6 个关节协调运动，并支持操作手实时控制和预定义轨迹回放两种工作模式。
- **技术方案**：
  - 6 个 DM 达妙电机分布在 CAN2（关节 3~6）和 CAN3（关节 1~2）总线上，各关节自由度覆盖 Yaw/Pitch/Roll
  - 采用**状态机架构**管理多种控制模式，`Joint_Control_Mode_Mangner()` 负责状态转移：
    - **Custom_Controller_Follow**：自定义控制器实时跟随。`Referee_Task` 通过 UART7 接收裁判系统协议封装的 26 字节控制器数据，`Parse_ControllerData_To_CtrllerRadian()` 将原始字节转换为 6 个关节的目标弧度值，经极性调整（不同安装方向的关节需翻转正负号）和安全限位后，通过 `Point_Publisher()` 写入 `Target_Point[6]` 结构体
    - **Rising_Mode**：预设抬升姿态（sw1=1 触发），所有关节快速移动到预定义安全弧度，用于上台阶前收回机械臂
    - **Frozen_Mode**：关节冻结，所有关节速度设为 0，保持当前位置不动
    - **Traj_Mode**：轨迹回放，通过 `osThreadFlagsSet(TRAJ_START_FLAG)` 唤醒 `Trajectory_Publisher_Task`，后者从 Flash 中读取预录制的 656 个六维关节角度采样点，以 30ms 间隔逐帧发布到 `Target_Point[6]`，完成后自动切回 Frozen_Mode
  - `Joint_Move_byPoint()` 统一执行关节运动：读取 `Target_Point[6]` 中的目标弧度和速度，调用 `PosSpeed_CtrlMotorDM()` 向每个 DM 电机下发位置-速度指令
  - 末端执行器（夹爪）由独立状态机 `Gripper_Control_Mode_Mangner()` 管理 Open/Close 两种模式
- **设计亮点**：控制模式与执行层完全解耦——所有模式最终都只需填写 `Target_Point[6]`，`Joint_Move_byPoint()` 统一执行，新增控制模式只需实现新的 Target_Point 生成逻辑即可
- **关键参数**：`[待补充：各关节角度限位范围、默认速度 0.2 rad/s、控制器映射系数、轨迹采样周期 30ms 等]`

### 3.4 软件看门狗与安全监控

- **解决的问题**：RoboMaster 比赛中电机 CAN 线断开、遥控器信号丢失、DM 电机过载等异常情况时有发生。若不及时检测和处理，机器人可能失控冲撞场地设施或对操作手造成安全威胁。需要一套多层次的安全监控体系。
- **技术方案**：
  - **DJI 3508 电机在线检测**：`Watchdog_Task`（1ms 周期）每 500ms 对比 6 个 3508 电机的 CAN 反馈帧计数器 `can_msg_t.cnt`。若计数器无增长则判定为离线，触发蜂鸣器报警——报警频率与离线电机数量成正比，操作手可通过音调快速判断故障范围
  - **DM 电机智能恢复**：除在线检测外，持续监控 DM 电机的状态码 `DM_motor_error_t`。检测到在线但处于 `Motor_DM_DISABLE` 状态时，以 200ms 周期发送 `Motor_DM_Enable()` 指令尝试重使能；检测到错误码（过压 0x8 / 欠压 0x9 / 过流 0xA / MOS 过温 0xB / 电机过温 0xC / 通信丢失 0xD / 过载 0xE）时，先调用 `Motor_DM_Clear_Error()` 再重使能，实现自动故障恢复
  - **遥控器超时保护**：持续对比 `remoter` 结构体的内容。若超过 60 秒所有字段无任何变化，判定为信号丢失或操作手离开，自动调用 `Chassis_ForcePowerOff()` 将底盘强制断电，DM 电机因失去周期性控制帧也会在短时间内自动停转
  - **蜂鸣器分级报警**：不同异常类型对应不同的蜂鸣器频率和节奏，便于在嘈杂的比赛环境中区分故障类型
  - 全部超时参数通过 `watchdog_config.h` 宏定义集中管理，可按场景快速调优
- **设计亮点**：采用 **检测-报警-恢复** 三级策略，DM 电机不仅报警还能自动恢复，大幅减少比赛中因瞬时故障导致的停机时间
- **关键参数**：`[待补充：实测超时阈值调优结果、各报警频率值等]`

### 3.5 双输入源控制逻辑切换

- **解决的问题**：比赛中需要同时支持遥控器（DBUS）和键盘鼠标两种操作方式——DBUS 适合大范围快速移动，键盘鼠标适合精细操作和视觉引导下的精确定位。两种模式需要能在比赛过程中实时无缝切换。
- **技术方案**：
  - 全局模式结构体 `Engineer_Mode_t` 包含三个独立维度：`Ctrl_Logic_Mode`（DBUS / Keyboard）、`Chassis_Ctrl_Mode`（Normal / Rising）、`Arm_Ctrl_Mode`（多种关节控制模式）
  - **B 键**实现 DBUS / Keyboard 控制逻辑的边沿触发切换。边沿检测在 `Referee_Task` 的 `Referee_KeyboardEdgeDetect()` 中完成，通过对比本帧与上一帧的按键状态，仅在按键从 0→1 的上升沿触发一次切换，避免长按重复触发
  - **C 键**在 Keyboard 模式下切换底盘 Normal / Rising 模式（仅 Keyboard 模式生效，DBUS 模式下由 sw2 拨码控制）
  - 切换时自动保存当前机械臂控制模式到 `arm_mode_backup`，切换回来时恢复，防止模式切换对机械臂状态的污染
  - 键盘数据通过 DBUS 协议的 14~15 字节传输（`key_code` 联合体），与遥控器通道数据在同一帧中，无额外通信开销
- **设计亮点**：三个模式维度完全正交——底盘模式、机械臂模式、控制源类型可以独立切换互不干扰，组合灵活度高

### 3.6 CAN 总线链表化消息管理

- **解决的问题**：系统使用 3 路 CAN 总线连接十余个设备（6 个 DJI 电机 + 8 个 DM 电机 + IMU），传统的 `switch-case` ID 分发方式在设备数量增多时维护困难、扩展性差。
- **技术方案**：
  - BSP CAN 层采用 **FreeRTOS 链表**（`List_t`）管理每条总线上的设备注册信息。每个 `can_msg_t` 节点包含端口号、CAN ID、8 字节数据缓冲区、数据长度和接收计数器
  - Module 层设备初始化时调用 `can_msg_add_item()` 将自身的 `can_msg_t` 注册到对应端口的链表，注册时自动检查 ID 重复
  - CAN 中断回调 `fdcanN_rx_callback()` 收到报文后，遍历对应端口的链表按 ID 查找匹配节点，找到后直接 `memcpy` 更新数据——整个过程在中断上下文中完成，延迟极低
  - 发送时 Module 层填充 `can_msg_t.data[]` 后调用 `can_msg_send_classical()`，BSP 根据 `port` 字段自动选择正确的 FDCAN 句柄
  - 支持标准帧、扩展帧、CAN FD 三种发送模式
- **设计亮点**：新增 CAN 设备只需创建 `can_msg_t` 并调用 `can_msg_add_item()` 注册，无需修改中断回调或 BSP 代码，实现了 **设备注册即用** 的零耦合扩展
